# Production Deployment Guide (Direct PostgreSQL API)\n\n## Overview\n\nThis guide covers deploying the GPS system to production with:\n- **Frontend**: React (Vite) → Vercel/Firebase Hosting\n- **API**: Express/Node.js → Railway/DigitalOcean/AWS\n- **Database**: PostgreSQL → Managed Service\n- **Auth**: Firebase Auth (no changes)\n\n**Removed**: ❌ Cloud Functions proxy layer\n\n---\n\n## Architecture\n\n```\nInternet Users\n      ↓\n  [Vercel Frontend]\n      ↓\n  [Railway API Server]\n      ↓\n  [PostgreSQL Database]\n```\n\n---\n\n## Prerequisites\n\n- [ ] Production Firebase project configured\n- [ ] PostgreSQL database service (CloudSQL, RDS, Managed PostgreSQL)\n- [ ] API server hosting (Railway, DigitalOcean, AWS)\n- [ ] Frontend hosting (Vercel, Firebase Hosting, Netlify)\n- [ ] Domain name (optional but recommended)\n- [ ] SSL certificates (auto-provided by most platforms)\n\n---\n\n## Step 1: Deploy PostgreSQL Database\n\n### Option A: Railway PostgreSQL (Recommended for simplicity)\n\n1. Go to railway.app\n2. Click \"New Project\" → \"Provision PostgreSQL\"\n3. Wait for database to initialize\n4. Copy connection string\n\n```bash\n# From Railway dashboard, copy DATABASE_URL\n# Format: postgresql://user:pass@host:5432/dbname\n```\n\n### Option B: AWS RDS PostgreSQL\n\n```bash\n# Create RDS instance\n# - Engine: PostgreSQL 15+\n# - Instance size: db.t3.micro (dev) or db.t3.small (prod)\n# - Multi-AZ: Yes (production)\n# - Storage: 100GB + auto-scaling\n\n# Get connection string from RDS dashboard\n```\n\n### Option C: DigitalOcean Managed Databases\n\n```bash\n# Create PostgreSQL cluster\n# - Get connection information\n# - Whitelist your API server IP\n```\n\n### Verify Database Connection\n\n```bash\ncd api\n\n# Test connection\nnpm install -g psql  # if needed\npsql \"your-connection-string\"\n\n# Should connect successfully\n```\n\n---\n\n## Step 2: Deploy Express API Server\n\n### Option A: Railway (Easiest)\n\n1. **Push code to GitHub**\n```bash\ngit add .\ngit commit -m \"Production deployment\"\ngit push origin main\n```\n\n2. **Deploy on Railway**\n   - Go to railway.app\n   - Click \"New Project\"\n   - Select \"Deploy from GitHub\"\n   - Choose your repository\n   - Select `api` folder (if needed)\n\n3. **Configure Environment Variables**\n   - Go to project settings\n   - Add environment variables:\n\n```bash\n# Database\nDATABASE_URL=postgresql://user:pass@host:5432/gps_app\n\n# Firebase\nFIREBASE_PROJECT_ID=your-project-id\nFIREBASE_SERVICE_ACCOUNT_PATH=/workspace/firebase-adminsdk.json\n\n# Company Domain\nCOMPANY_EMAIL_DOMAIN=letstransport.team\n\n# Server\nNODE_ENV=production\nPORT=3001\n```\n\n4. **Deploy**\n   - Railway auto-deploys\n   - Get URL: e.g., `https://api-prod-xxxxx.railway.app`\n\n### Option B: DigitalOcean App Platform\n\n1. **Create `railway.json` or DigitalOcean App Spec**\n\n```yaml\nname: gps-api\nservices:\n  - name: api\n    dockerfile_path: Dockerfile\n    environment:\n      - key: DATABASE_URL\n        value: ${{db.DATABASE_URL}}\n      - key: FIREBASE_PROJECT_ID\n        value: your-project-id\n      - key: NODE_ENV\n        value: production\n```\n\n2. **Push to GitHub**\n3. **Connect DigitalOcean to GitHub**\n4. **Deploy**\n\n### Option C: AWS EC2 + PM2\n\n```bash\n# SSH into EC2 instance\nssh -i key.pem ec2-user@your-instance-ip\n\n# Clone repository\ngit clone your-repo.git\ncd gps/api\n\n# Install Node.js\ncurl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -\nsudo apt-get install -y nodejs\n\n# Install dependencies\nnpm install\n\n# Create .env\ncat > .env <<EOF\nDATABASE_URL=your-connection-string\nFIREBASE_PROJECT_ID=your-project-id\nNODE_ENV=production\nPORT=3001\nEOF\n\n# Install PM2\nsudo npm install -g pm2\n\n# Start with PM2\npm2 start src/server.ts --name gps-api --env production\npm2 save\npm2 startup\n\n# Setup Nginx reverse proxy (see below)\n```\n\n---\n\n## Step 3: Setup Nginx Reverse Proxy (for EC2/self-hosted)\n\n```bash\n# Install Nginx\nsudo apt-get install nginx -y\n\n# Create config\nsudo nano /etc/nginx/sites-available/gps-api\n```\n\n```nginx\nserver {\n    listen 80;\n    server_name api.yourdomain.com;\n\n    # Redirect HTTP to HTTPS\n    return 301 https://$server_name$request_uri;\n}\n\nserver {\n    listen 443 ssl http2;\n    server_name api.yourdomain.com;\n\n    # SSL certificates (use Let's Encrypt)\n    ssl_certificate /etc/letsencrypt/live/api.yourdomain.com/fullchain.pem;\n    ssl_certificate_key /etc/letsencrypt/live/api.yourdomain.com/privkey.pem;\n\n    # Proxy to Express\n    location / {\n        proxy_pass http://localhost:3001;\n        proxy_http_version 1.1;\n        proxy_set_header Upgrade $http_upgrade;\n        proxy_set_header Connection 'upgrade';\n        proxy_set_header Host $host;\n        proxy_cache_bypass $http_upgrade;\n        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;\n        proxy_set_header X-Forwarded-Proto $scheme;\n    }\n}\n```\n\n```bash\n# Enable site\nsudo ln -s /etc/nginx/sites-available/gps-api /etc/nginx/sites-enabled/\n\n# Test config\nsudo nginx -t\n\n# Restart\nsudo systemctl restart nginx\n\n# Setup SSL with Let's Encrypt\nsudo apt-get install certbot python3-certbot-nginx -y\nsudo certbot --nginx -d api.yourdomain.com\n```\n\n---\n\n## Step 4: Deploy Frontend\n\n### Option A: Vercel (Recommended)\n\n1. **Connect to Vercel**\n   - Go to vercel.com\n   - Create new project\n   - Import GitHub repository\n\n2. **Configure Build Settings**\n   - Build command: `npm run build`\n   - Output directory: `dist`\n   - Install command: `npm install`\n\n3. **Set Environment Variables**\n   ```bash\n   VITE_FIREBASE_API_KEY=your-key\n   VITE_FIREBASE_AUTH_DOMAIN=your-project.firebaseapp.com\n   VITE_FIREBASE_PROJECT_ID=your-project-id\n   VITE_FIREBASE_STORAGE_BUCKET=your-project.appspot.com\n   VITE_FIREBASE_MESSAGING_SENDER_ID=your-sender-id\n   VITE_FIREBASE_APP_ID=your-app-id\n   \n   # CRITICAL: Point to your deployed API server\n   VITE_API_BASE_URL=https://api-prod-xxxxx.railway.app\n   VITE_FO_API_BASE_URL=https://api-prod-xxxxx.railway.app\n   ```\n\n4. **Deploy**\n   - Vercel auto-deploys\n   - Get URL: `https://your-app.vercel.app`\n\n### Option B: Firebase Hosting\n\n```bash\n# Build\nnpm run build\n\n# Deploy\nfirebase deploy --only hosting\n```\n\nEnvironment variables are set in `vite.config.js` or `.env.production.local`:\n\n```bash\n# .env.production.local\nVITE_API_BASE_URL=https://your-api-url.com\nVITE_FO_API_BASE_URL=https://your-api-url.com\n```\n\n### Option C: Netlify\n\n1. Connect GitHub repository\n2. Build settings:\n   - Command: `npm run build`\n   - Directory: `dist`\n3. Add environment variables\n4. Deploy\n\n---\n\n## Step 5: Configure DNS\n\n### Frontend Domain\n```bash\n# Point to Vercel / Firebase / Netlify nameservers\n# (provided by each service)\n```\n\n### API Domain (if using custom domain)\n```bash\n# Create A record pointing to your API server\n# api.yourdomain.com → your-api-ip-or-railway-url\n```\n\n---\n\n## Step 6: Verify Production Deployment\n\n### Health Checks\n\n```bash\n# Frontend loads\ncurl https://your-app.com\n# Should return HTML\n\n# API responds\ncurl https://api.yourdomain.com/health\n# Should return {\"status\": \"ok\"}\n\n# Database connected\ncurl https://api.yourdomain.com/health/db\n# Should return {\"database\": \"connected\"}\n```\n\n### Smoke Tests\n\n1. **Auth Flow**\n   - Login with test user\n   - Verify token works\n   - Verify database user created\n\n2. **Request Workflow**\n   - Create request (FO)\n   - Approve request (RH)\n   - Approve payment (Payment)\n   - Notify vendor (Vendor)\n\n3. **Email Flow**\n   - Verify OTP emails sent\n   - Verify notification emails sent\n\n---\n\n## Security Checklist\n\n- [ ] PostgreSQL username/password strong\n- [ ] Database restricted to API IP only\n- [ ] API has rate limiting\n- [ ] API behind HTTPS/TLS\n- [ ] Firebase rules updated for production\n- [ ] Environment variables NOT in git\n- [ ] Secrets manager used (if available)\n- [ ] Backups enabled for PostgreSQL\n- [ ] Monitoring/logging enabled\n- [ ] CORS configured correctly\n\n---\n\n## Monitoring & Logging\n\n### Railway\n- Built-in logging dashboard\n- View logs in Railway console\n\n### DigitalOcean\n```bash\n# View logs\ndigitalocean apps logs your-app-id\n```\n\n### EC2 + PM2\n```bash\n# View logs\npm2 logs gps-api\n\n# Monitor\npm2 monit\n```\n\n### Application Logging\n\nAdd to [api/src/server.ts](api/src/server.ts):\n\n```typescript\nimport winston from 'winston';\n\nconst logger = winston.createLogger({\n  level: process.env.LOG_LEVEL || 'info',\n  format: winston.format.json(),\n  defaultMeta: { service: 'gps-api' },\n  transports: [\n    new winston.transports.File({ filename: 'error.log', level: 'error' }),\n    new winston.transports.File({ filename: 'combined.log' }),\n  ],\n});\n\nif (process.env.NODE_ENV !== 'production') {\n  logger.add(new winston.transports.Console({\n    format: winston.format.simple(),\n  }));\n}\n```\n\n---\n\n## Rollback Procedures\n\n### If API deployment fails\n```bash\n# Railway: Automatic previous version available\n# Simply redeploy or use Railway's rollback feature\n\n# EC2: Use git revert\ngit revert HEAD\nnpm install\npm2 restart gps-api\n```\n\n### If frontend deployment fails\n```bash\n# Vercel: Automatic previous deployment\n# Click \"Deployments\" → select previous → \"Promote to Production\"\n```\n\n---\n\n## Cost Estimates (Monthly)\n\n| Service | Min Cost | Notes |\n|---------|----------|-------|\n| PostgreSQL | $10-50 | Managed service |\n| API Server |
